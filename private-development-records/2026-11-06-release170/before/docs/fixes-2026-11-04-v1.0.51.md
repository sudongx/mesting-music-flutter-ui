# 1.0.51 页面导航、登录、列表滚动与 SDK 更新

本轮范围经用户确认覆盖两个平台所有普通二级、三级及更深页面；“我的→我的消息”是复现场景，不是修复范围限制。特殊播放器、搜索展开和头像预览保留既有进入形式，并沿自身路径返回。本轮仅本地交付，不访问手机、ADB、真实音乐账号或业务后台，不提交、推送或发布。

## 导航根因和共用修复

- Flutter 3.41.9 的 `MaterialRouteTransitionMixin` 提供了委托动画函数；当前主题没有对应委托时该函数返回 null，但框架仍将前页 secondary animation 代理为零。前页因此无法在返回时从左方恢复。`MestingPageRoute` 在当前内部 Beta UI 上明确不提供此委托，Stable 保留原行为。
- 四个保留 Tab 的实际分支根页面，以及最外层 music shell，都接入只处理 secondary animation 的根页面；Tab 切换继续由保留状态的 PageView 驱动。
- 登录、设置等 `betaEntryRoute` 统一使用可反向的 `BetaContentRoute`，不再另建缺少 secondary animation 的普通 PageRouteBuilder。资料编辑和登录路由也使用普通页契约。
- 关注/粉丝和有声书专辑的两个旧 Cupertino 入口，在当前 UI 中接入共用普通路由；Stable 继续 Cupertino 行为。共享 Material、content、entry 和 Cupertino 兼容入口可任意混合多层导航。
- 同一个水平 Tween 同时用于正向和反向；进入由右向左，当前页返回由左向右，前页同时从左方回到原位。不在 pop 时重新选择一个进入方向。

核对了源码全部原始路由构造点，普通调用方不再直接创建 MaterialPageRoute/CupertinoPageRoute。运行时覆盖 16 种混合路由相邻组合、四个真实 Tab × 七类真实路由共 28 条路径，以及生产网易云“我的消息→会话”入口两次返回的中间坐标。不是仅检查孤立 Tween 或最终落点。

## 双平台登录全屏和逐级返回

平台切换页、登录方式页及所有 PlatformAccountPage 都登记实际路由的底部控件覆盖状态。复用现有绘制/命中测试门控，登录过程中导航、搜索和播放控件一起隐藏；回到普通页面恢复。

网易云扫码、手机验证码、手机号与密码、邮箱与密码；酷狗手机号、酷狗扫码、微信扫码、QQ扫码均覆盖。顶部返回、系统返回、左侧和右侧边缘侧滑都使用当前实际 Navigator 逐级返回。测试包含先保留网易云再打开酷狗，以及反向场景；不会把原平台登录态带成另一个平台的账号管理页，也不会通过返回提交新登录。

## 加载位置与原内容保留

- RefreshIndicator 在顶部开始任何拖动时就可能报告 drag；只有实际拉到 leading overscroll 才显示顶部刷新动画，向后面的歌曲滚动不再把正常开始手势当作刷新。
- 首屏等待居中、明确下拉刷新在顶部、滚动到下一批内容的等待在末端。后续批次暂时占满视口时，零 cutoff 也不再被误判为首屏。
- 每日推荐刷新保留已挂载歌曲、封面和滚动位置，沿现有内容边界替换成功数据；不把等待视图换到原列表顶部。

## 上次播放定位与回到顶部

`SongListScrollMotion` 共用距离相关、420～1000ms 的连续滚动。未构建的懒列表目标也通过 animateTo 构建沿途内容，再精确对齐；取消了先 jumpTo、再仅动画最后一小段的行为。定位成功仍只短暂高亮两秒，不发播放指令。手动滚动、账号/列表切换及新快捷动作会中止旧定位的后续操作。系统减少动态效果开启时继续立即定位。

## Ring Download SDK

官方正式源码由 1.1.0 升级至 1.1.2；官方 ZIP SHA-256 为 `387a6b8f5f3ec1bf2e0551d57427f6053a841fb90dd1b2bd670dad376d143665`，242 项原始文件逐项比对。宿主 Dart 3.11.5 下仅移除前序长度检查已经证明非空的一处重复 `!` 并补注释，其余 241 项保持原始字节；这项分析兼容不改变传输流程。只更新 path 依赖锁中的 SDK 版本，其余宿主依赖版本、原签名、music appId、更新源、原安装器和 P2P/P8P 开关保留，用户上传仍为关闭。

新版接收缓冲原生库有四个架构，正式 Music APK 继续只包含双 ARM；x86/x86_64 排除，不随一个无对应引擎的 SDK 库广告额外架构。先验证官方 ARM 库原始哈希，再用同版 NDK 的 `llvm-strip --strip-unneeded` 重现 AGP 正式构建的去符号处理；结果与实际 APK 两份库逐字节一致，并核验 ELF、对齐与 JNI 保留。原八份 SDK 库及定制引擎/七份玻璃 shader 继续比较。
