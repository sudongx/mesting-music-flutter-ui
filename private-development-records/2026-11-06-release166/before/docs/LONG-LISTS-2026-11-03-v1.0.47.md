# 1.0.47 / code68 长列表、足迹与收藏排序

用户已确认：范围覆盖整个 App 的长列表；支持分页的来源按需读取；确实不能分页的来源允许完整响应后台处理、分批展示。另两项为足迹仅切换下方报告、酷狗喜欢按收藏时间最新优先。本轮不访问手机、ADB、真实音乐账号或业务后台，不提交、推送或发布。

## 数据和界面边界

列表首先取得约 30 条详情，滚动接近末尾时续载。游标按来源消耗的记录数前进，不能按去重后的可见条数前进。网易云歌单先取有序 ID 索引，再取本批详情；不再先补全所有歌曲详情后在界面上 `skip/take`。缺失歌曲不改变后续 ID 的游标。加载失败保留已显示内容，并保留重试入口。

大 JSON 的 UTF-8/解码、缓存复制/序列化、完整名单转换及部分统计交由 worker；小响应保持低开销直接处理。128 KiB 的判断采用有上限的估算，不能先在主线程序列化整个对象再决定是否移出主线程。原缓存的账号、凭证、epoch、失败保留旧值和封面就绪替换机制继续生效。

完整收藏状态与浏览窗口分离。网易云用 `/likelist`，本地用 ID-only 查询；酷狗复用收藏索引。收藏内搜索读取完整当前账号收藏，不调用全平台搜索。播放全部、整份歌单下载和本地歌单选曲仍取得完整集合；普通点播保留既有显式点播语义，不为点一首歌偷偷加载整个集合。本地拖动排序保留完整次序，播放队列不按视口截断。

## 酷狗收藏顺序的协议限制

官版下载站取得的酷狗概念版 5.2.9 / code11590 经离线定点静态核对，私人歌单请求含 page/pagesize；解析器读取 `collecttime`、fileid、hash、sort、count 和 list_ver。所核请求没有倒序读取参数。工程 Rust 转发同一私人歌单接口，未在中途丢弃原始记录字段。这里只证明所查请求和字段，不证明官版所有客户端/所有接口都没有其他排序能力，也未运行官版账号。

因此酷狗“我的喜欢”首次需要取得完整记录建立账号内索引，后台按真实收藏时间全局排序后再给界面 30 条一批的结果。秒/毫秒时间均归一化；相同时间保持来源顺序，fileid 与 hash 分离保留。后续浏览、完整搜索和收藏状态复用该索引及原私有响应缓存；没有逐页反转，也没有调用云端重排写接口。普通歌单继续按需请求。若真实响应缺少收藏时间，保留其来源顺序，不用歌曲名或 hash 猜测收藏先后。

私有研究材料保存在 `.codex-artifacts/2026-11-03-release147/private/`，官方 APK/反编译正文和诊断材料均不放入产品或完整源码交付。REA 最终会话没有保留记录；定点调用返回结果已单独存档，不能把空会话导出冒充证据包。此前网易云整包静态分析超时仍为未知边界，本版没有声称复现官版内部实现。
