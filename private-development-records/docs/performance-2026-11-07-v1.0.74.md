# 1.0.74/code95：性能、缓存与按需加载

2026-11-07（北京时间）。用户确认后实施，允许实机性能对比、保留数据升级与复测；保留完整玻璃、角色动画和现有功能。启动仍进入默认页面，复用已成功加载过的数据与封面，不恢复上次的路由。临近视口允许少量预取。

## 实现

- 网易云、酷狗共用的首页把连续普通栏目交给懒构建的 SliverList，真实 sliver 保持原位置；水平栏目继续按需构建。启动只保留首屏及附近模块的恢复订阅，专辑、主题、场景等下方栏目进入附近才建立订阅与刷新任务。
- 汽水增加独立的显示数据缓存策略，复用现有持久缓存、图片准备和刷新通知。缓存键隔离版本、平台协议、账号、查询、模式与游标；凭据、播放授权、媒体解析、权益、图片上传授权与写入不使用旧响应。显示投影移除嵌套认证/媒体授权字段。缓存可用时先展示旧数据与图，新数据及对应图片就绪后更新；失败保留旧内容。首次访问、无缓存或已删除的缓存仍需正常加载。
- 汽水发现、音乐、我的、历史使用同一组可恢复的页面 provider，冷启动不再把汽水当成酷狗分支初始化。歌曲/歌手搜索和歌手资料、作品页观察各自已加载的批次，后台更新保留其他页及滚动位置；续载边界不一致时拒绝拼接不一致结果。
- 汽水歌单先读最多100首，离底部一屏以内才读后续批次。翻页、重载和离页有独立取消代次。播放全部、随机、批量、下载全部、全歌单搜索和排序仍显式取得完整列表，不把首批当成全部。
- 账号资料同账号刷新不再清空可见快照；切换账号/凭据仍隔离。图片请求完成回调按当前请求去重，来源、尺寸、DPR、重试或可见性改变才重新解析；隐藏页图片不再参与其他页面的刷新准备。
- 补查复现并修复汽水切换账号时的短暂旧资料显示：Riverpod依赖重载会在内部保留上一份数据，新账号页面不再直接解包这份旧值；当前账号自己的刷新继续保留原内容。新增真实Widget账号切换回归，先确认旧资料不可见，再确认新请求完成后显示新资料。
- 大型缓存的完整性校验、图片索引编码/解码和启动队列解析使用后台工作。原存储格式与哈希算法保持兼容，成功图片解析仍等待所属索引的原子写入。
- 缓存数据按账号/查询共享；进行中的网络请求另按取消归属隔离。取消旧页面后重载不会复用已经取消的请求，另一页面也不会被连带取消。业务拒绝由页面明确显示、用户重试，不交给 provider 自动重试而长期停在加载状态。
- 首次实机候选发现：启动的磁盘缓存未命中已交给正常请求接管，但旧Future仍把内部异常提示在已加载的页面上。已改为以当前provider的错误为准，缓存未命中不作为业务失败展示；同时修正资料页的旧错误提示，并补真实启动次序的回归。该未定稿候选与首次安装收据单独保留，最终包重新构建、安装和验收。
- 冷启动连续图里曾观察到后续可视图片占位，当时尚未隔离人工滚动；专项受控回归独立确认了汽水图片DTO没有完整进入旧图片准备链的问题。新增纯数据的封面投影契约，由汽水适配器复用真实显示层的URL/URI/模板解析，向共享图片准备器提供首选封面；原始备用CDN候选保持。共享准备器使用该投影等待新图下载与解码，再允许响应替换。合成PNG、持久快照和受控HTTP回归验证了就绪、失败和账号取消三种结果；网易云/酷狗原有图片路径同时回归。最终受控设备窗口里目录没有发生变化，因此真实服务器新旧目录切换的整段过程未单独验明；不把定点截图说成全程无占位证明。
- 修正诊断器直接滚动根 PageController 的做法：根 Tab 使用生产回调，普通左右分页排除根视口。诊断增加汽水真实页面，缺少登录/歌曲/歌单时如实跳过，不造资料或自动播放。

## 官版对照的范围

对照的是手机当前安装的网易云9.6.15、酷狗20.8.6和汽水21.5.0，并结合REA静态调用链。网易云、酷狗本地APK与手机公开APK的SHA256一致；汽水同版本完整APK不同，本轮选取的classes6.dex与手机当前APK逐字节一致，不能说完整APK相同。

- 网易云 `ImagePrefetchImpl.prefetch/cancel` 使用磁盘图片预取、去重、批次登记及取消关闭 DataSource。Mesting 对应采用有界预取、解析复用和可见性/取消归属。
- 酷狗日推 `dailybills.a.l` 从持久键读取缓存，再按逻辑列表键匹配；`DailyBillCacheModel.e` 验证格式版本并恢复页数组。Mesting 保留其独立列表/分页语义并持久化可展示结果。此静态范围没有证明所有酷狗页面都使用同样刷新顺序。
- 汽水 `PreloadTabDataTask.e` 在页面完成且消息队列空闲的阶段，按配置预取发现或我的数据，并有一次性保护。是否启用取决于运行时配置。Mesting 把首屏恢复与后续按需工作分开，不把“所有内容严格等可见才加载”冒充三家共同规则。

没有移植官版的广告、付费弹层、动态实验或私有凭据；Flutter 的渲染与状态管理仍按本项目架构实现。未修改独立签名助手或NAS部署。

主机回归、源码/签名/包内检查与真实设备性能分别记录，最终数字见本版验证JSON和性能JSON。重复运行按完整文件替换，不叠加用例数。旧原生Media3/CENC结果只在输入哈希相同时继承，不冒充本轮新运行。
