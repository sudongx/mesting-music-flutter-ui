# 汽水账号参与签名：客户端与自建助手对接

此说明对应本地 1.0.72/code93。用户已明确允许新增此开关，范围仅为自己管理的 HTTPS NAS。此说明不是服务器部署记录；本轮没有连接、部署或修改 NAS，也没有读取真实账号 Cookie 或访问令牌。

## 客户端行为

在「我的 → 设置 → 汽水签名服务」中开启「账号参与签名」，再点击「保存并使用」。旧加密设置缺少此字段时按关闭读取；保存记录增加布尔值 `accountBoundSigning`，账号登录资料仍由原账号存储负责。

只允许自建 HTTPS 地址开启此功能。HTTP 地址仍可用于原有匿名签名，但开启账号参与时会拒绝保存。已知公共签名服务即使被手动填写为自建地址，也不能开启账号参与。助手调用不跟随重定向，TLS 证书仍按正常规则校验。

仅 `https://api.qishui.com/luna/pc/track_v2` 的签名输入可以增加当前官方请求适用的 `cookie` 头。签名前固定这份 Cookie，随后官方请求发送同一份内容。其他写入和下载资格签名继续保持原有匿名助手输入。CSRF 和账号 token 的独立请求头不交给助手，完整账号 Cookie jar、其他平台资料及 PlayAuth 不交给助手。

「测试连接」始终使用匿名请求，即使已开启此开关，也不发送音乐账号 Cookie、播放歌曲或查询个人权益。测试通过不能证明整曲权益可用。

## 助手需要支持的输入

沿用已有 `/config` 和 `/sign` 接口及访问令牌鉴权，不新增业务代理。`/config` 仍返回已配置的 PC `device_id`、`iid`、`fp`、`user_agent`。`/sign` 的 JSON 字段保持 `url`、`method`、`body`、`headers`、`ts_ms`；仅上述媒体路径在用户开启后可能于 `headers` 中增加小写 `cookie`。

助手应将这份 Cookie 原样用于该次签名计算，不能在签名前移除、改变顺序、增添其他账号 Cookie 或换用助手自己的账号。请求 URL、正文及 `x-ss-stub` 也必须与客户端输入一致。应限制合法官方路径、正文大小和请求头长度，并继续拒绝任意代理与跳转。

返回仍只需完整 `x-helios`、`x-medusa` 和与请求一致的 `device_id`。客户端不会接受助手返回的 Cookie、Authorization、CSRF 或其他账号头，也不会接受助手改写自建模式下的 URL 查询参数。

请勿在助手、反向代理、错误追踪或调试日志中保存请求正文里的 Cookie。客户端导出的连接诊断只记录 `accountCookieSigned` 布尔值，不记录 Cookie、令牌、媒体地址或账号 ID。客户端不能替服务器保证日志配置；当前部署是否接受 Cookie 字段仍需另行核对。

若助手旧白名单拒绝此字段，可能返回参数错误；若助手静默删除此字段，签名仍可能不匹配。需要由独立助手维护方按本说明适配，不能以客户端开关已出现宣称 NAS 已升级。

## 整曲与权益的边界

本地保留的参考实现显示，官方媒体请求的 Cookie 应参与签名。这是修正客户端输入的一条依据，尚不能证明用户这次试听或 301 的唯一原因。

「免费听与权益」读取当前扫码会话的 `commerce_info`，分别识别 `play_entitlements.expire_at`、`incentive.expire_time` 和会员状态。活动日期、最大可领天数及已完成任务数不能作为免费听到账证明。此版本不自动领取广告奖励，也不伪造广告凭证或免费听参数。
