# R4：首次恢复房间的媒体前台承载与双开验收

2026-11-03，Asia/Shanghai。版本1.0.45/code66，私有诊断候选，正式冻结基线1.0.44。R2/R3的历史经过见 `SYNC-DUAL-APP-2026-11-03-v1.0.45.md`。

## 修复范围

R2已经补上常规同步漏读权威快照的问题，正常媒体建立后后台切歌有实测成功。但首次恢复且接收端从未播放时，既有媒体服务尚未前台化，后台脉冲数秒后停止。R3单独让有效房间持唤醒锁仍失败，已撤回。

原会话已写入R4，新增媒体编译依赖后中断；本轮从该中断位置继续。R4在有效后台房间请求脉冲时复用既有 `AudioService.instance`，通过现有前台服务API及通知ID1124、`com.mesting.music.playback`渠道建立承载。继承当前媒体会话和真实播放状态，不启动第二个服务、不伪造playing、不播放静音音轨。通知文字只描述正在同步好友状态；普通构建的一起听日志开关仍默认关闭。

- `MestingTogetherMediaLease.java`：固定版本audio_service 0.18.19的窄桥接，在主线程操作服务，保持通知标记，正常播放替换通知后不撤销真实播放所有者。直接媒体编译引用使用同版本AndroidX media 1.7.0的compileOnly依赖；Java按UTF-8读取通知文字。
- `TogetherMediaLeaseCoordinator.kt`：独立所有者状态机，使用身份集合，重复请求幂等、旧引擎退出不撤销新引擎，最后所有者释放时才交给Android端判断通知归属。
- `TogetherBackgroundPlugin.kt`：只在有效后台房间的可交付请求中取得媒体承载，禁用、租约失效或引擎销毁时释放；唤醒锁仍以现有前台媒体服务及90秒有界超时为条件。
- `TogetherPulseScheduler.kt`：只新增固定枚举诊断阶段；`ic_stat_together.xml`使用本地通知图标。

不更换原签名、Flutter定制Release引擎、SDK、完整玻璃或播放协议。509个Dart源文件与R2冻结源码逐文件一致。
